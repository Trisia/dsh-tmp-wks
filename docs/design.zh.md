# 临时工作区设计说明

本文说明 dsh-tmp-wks 的工作机制：临时工作区如何创建、删除授权依据什么、以及各项配置如何影响行为。面向使用与维护本插件的人，不涉及具体实现约束。

## 它解决什么问题

想快速问一个临时问题，通常得先退出当前会话、建一个目录、回来把工作目录指过去，用完再手动清理；忘记清理时，几个会话还会共用同一个目录而互相干扰。

本插件把这一串操作收成一次点击：就地建一个一次性目录并立刻在其中开会话。

## 核心设计：命名与授权分离

插件的目录名带前缀（默认 `tmp-`），但**前缀只负责命名，不参与删除授权**。

删除授权由 Host 侧的一份记录决定：插件每创建一个目录，就把它的绝对路径记下来。删除时查这份记录，是记录里的才允许删。

这样设计的原因很直接：如果拿前缀当"这是我建的"的凭据，那么一旦改了前缀，早先按旧前缀建的目录就再也删不掉了，只能手动处理。把授权建立在记录上，前缀就变成一个纯粹的名字偏好，随时可改。

记录由 Host 保管在 DSH 的存储中，与浏览器无关，因此清理浏览器数据或换一个客户端都不会丢失。

## 创建流程

1. 确保存放目录存在（首次使用时可能还没有）。
2. 用「前缀 + 6 位随机字符」拼出目录名并创建。随机字符剔除了容易看错的 `0/O/1/l/I`。
3. 名字被占用时自动换一个重试，最多 5 次。
4. 把目录登记为 DSH 工作区，并写入创建记录。
5. 返回工作区标识，界面据此直接进入该工作区的会话。

记录是在返回之前写入的：万一记录写不进去，宁可整体失败，也不会留下一个后续删不掉的目录。

## 删除流程

删除是一个**先校验、后动手**的两段式过程。

### 第一段：校验

Host 依次检查三件事，任何一条不满足都直接拒绝，**磁盘不会被触碰**：

| 检查 | 拒绝时返回 | 含义 |
|---|---|---|
| 目标不是存放目录本身 | `refused-container` | 防止把整个存放目录连锅端掉 |
| 目标位于存放目录之内 | `refused-outside` | 防止删除范围溢出到目录之外 |
| 目标在创建记录中 | `refused-unknown` | 不是本插件建的，不予删除 |

通过校验后，还会把路径解析一次真实路径再复查前两项。这一步针对的是软链接：一个位于存放目录内、但实际指向外部的软链接，不能在解析后被当成目录内路径删掉。

### 第二段：执行

校验通过后看配置项 `confirmDirDelete`：

- **开启（默认）**：先回一个 `needs-confirm`，不删任何东西，由界面询问后再调一次，这时才真正删除。
- **关闭**：直接删除，不问。

判断始终由 Host 做：界面只根据返回的结果码决定渲染什么，不自行推断。

删除成功后，对应记录一并撤除。若目录本就不存在，按「已经删掉了」处理（返回 `missing`），不算失败。

### 提示出现在删除之后

DSH 内置的「删除工作区」对话框只移除列表登记，并明确告知「文件夹与会话记录会保留」。它既不是可插入的扩展点，也拦不住，因此本插件**无法在删除前插入询问**。

实际做法是事后发现：界面比对目录记录与工作区列表——记录里存在、工作区列表里却已没有的临时目录，就判定为「刚被内置入口删掉了工作区」，随即询问是否清理。

因此顺序是「先删工作区，再问要不要删目录」，与直觉上的「删除前询问」不同。

**只对本次会话中发生的删除提示。** 启动时就已经存在的孤儿目录（例如上次选了「保留」，或工作区列表早已不同步）不会弹提示——用户并没有做任何删除动作。界面在首屏数据齐备时先记下基准，之后才失去工作区的目录才算「刚被删除」。

若配置 `confirmDirDelete` 关闭，则完全不询问，目录留在磁盘上由用户自行处理。

## 配置项

配置页位于侧栏**插件**页中本插件那一行，保存后写入当前 profile 的 `cordis.patch.yml`；也可以直接编辑该文件。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `tempDir` | 操作系统的临时目录 | 存放临时工作区的容器目录。留空即用系统临时目录（`$TMPDIR`、`%TEMP%` 等）；填相对路径时基于 DSH 主目录解析，填绝对路径则直接使用 |
| `dirPrefix` | `tmp-` | 新建目录的名称前缀。必须是单个目录名，不能包含路径分隔符 |
| `confirmDirDelete` | `true` | 工作区被删除后，是否询问要不要清理对应的磁盘目录 |

`tempDir` 的默认值取自运行环境，各平台的来源不同：Linux/macOS 读 `$TMPDIR`，Windows 读 `%TEMP%` 再退到 `%TMP%`，两者都没有时用平台自身的默认位置（如 Linux 的 `/tmp`）。因此一个默认路径形如：

```
/tmp/tmp-k7mq2z
```

**插件启动时就把空值物化为完整绝对路径。** 配置留空（或从未配置）时，Host 在启动那一刻调用系统的临时目录解析，得到一个完整路径并固定下来；运行期与配置页看到的都是这个完整路径，不存在「空串」的中间状态。因此客户端无需自行推断，配置页留空即表示「交给系统临时目录」。

这一物化只发生一次，取值在整个进程生命周期内稳定，不会因为别处改了环境变量而中途漂移。

优先级始终是「用户显式配置 > 系统临时目录 > DSH 主目录」：仅当操作系统连临时目录都给不出时，才回退到 DSH 主目录（默认 `~/.dsh`，可用 `$DSH_HOME` 覆盖）下的 `tmp`。

### 改动配置的影响

- **改 `tempDir`**：只影响之后新建的目录。存放目录之外的旧目录会被 `refused-outside` 拒绝删除，需手动清理。
- **改 `dirPrefix`**：只影响之后新建目录的名字。已有目录仍可正常删除，因为授权依据是记录而非名字。
- **改 `confirmDirDelete`**：立即生效，无需重启。

## 界面入口

| 入口 | 位置 | 作用 |
|---|---|---|
| 新建临时会话 | 侧边栏底部 | 创建临时工作区并进入会话 |
| 清理提示 | 工作区被删除后自动出现 | 询问是否清理对应的磁盘目录 |
| 配置页 | 侧栏「插件」页本插件那一行 | 修改上述三项配置 |

## 与 dsh 的版本兼容

插件支持哪些 dsh 版本，由 `package.json` 的 `engines.dsh` 单条声明：

```
>=0.2.0-rc.2 <0.3.0-0
```

即 0.2.0-rc.2 及 0.2.x 的各版本都可加载，0.3.0 起不再声明兼容。

兼容性不通过 `peerDependencies` 表达。dsh 启动时会逐个校验插件中所有 `@deepseek-ai/dsh*` 的 peer 范围是否满足当前运行时，任一不满足就整包跳过；把 peer 钉死到某个具体版本（例如 `0.2.0-rc.2`）后，dsh 每发一个新版本都会让插件被判为不兼容。改用 `engines.dsh` 后 dsh 只按这一条范围判断，peer 仅作为构建期的类型来源保留。

上界写成 `<0.3.0-0` 而非 `<0.3.0`：dsh 校验时带 `includePrerelease`，`0.3.0-rc.1` 会被算作小于 `0.3.0`，只有 `-0` 上界才能把 0.3.0 的预发布版本挡在外面。

运行时版本落在范围外时，dsh 在启动日志中提示 `skipping profile bundle` 并跳过本插件：侧边栏不出现任何入口，磁盘上已有的临时目录不受影响。此时只能升级到支持当前 dsh 的插件版本，或用 `dsh plugin allow-version` 对该精确版本单独放行。

## 结果码

界面显示的信息由这些结果码驱动，便于按界面语言呈现：

| 结果码 | 含义 |
|---|---|
| `deleted` | 已删除 |
| `missing` | 目录本就不存在，等同于已删除 |
| `needs-confirm` | 校验通过，但需要用户确认后才删 |
| `refused-container` | 目标是存放目录本身，拒绝 |
| `refused-outside` | 目标在存放目录之外，拒绝 |
| `refused-unknown` | 目标不在创建记录中，拒绝 |
| `delete-failed` | 删除过程中出错，附带原因 |
